# Script structures

Read this when drafting. Pick the skeleton for the format, then fill it with the creator's own
material. Timings are guides, not rules.

## Pacing basics

- **Speaking speed**: about 2.5 words per second (~150 words per minute) for a calm explainer;
  closer to 3 words per second for energetic short-form. A 45-second Short is ~110-130 words.
- **Something changes every few seconds** on short-form: a new shot, zoom, screen, caption or
  on-screen element. On long-form, re-hook every 60-90 seconds: a new question, a reveal, a "but".
- **Connect beats with "but" or "so", never "and then".** "I tried X, *but* it broke, *so* I tried
  Y" keeps tension. "I did X, and then Y, and then Z" is a list, and lists leak viewers.
- **Write the first and last lines first.** The last line should land a point (ideally one worth
  sharing) and, on short-form, can loop back into the first line so a rewatch feels natural.
- **One video, one idea.** If you're explaining two things, it's two videos.

## Short-form (Shorts, TikTok, Reels), 20-60 seconds

| Beat | Time | Job |
|---|---|---|
| **Hook** | 0-3 s | First frame + spoken line + on-screen text (see hooks.md) |
| **Context** | 3-8 s | Why this matters to the viewer, in one sentence |
| **Body** | 8-40 s | 2-4 steps or points, each with something new on screen |
| **Payoff** | last 5-10 s | Deliver exactly what the hook promised; show the result |
| **Close** | last 1-3 s | One line: a takeaway, a loop back to the hook, or one ask. Not three asks |

Over 60 seconds is fine when the content earns it (tutorials), and TikTok's Creator Rewards only
pays for videos over a minute, but every extra second must hold attention. When in doubt, cut.

### Short-form skeletons for tech

- **Tool trick**: problem the viewer has (hook) → the trick on screen → the result → "save this for
  when you need it" or a loop.
- **Mini-tutorial**: end result first → step 1, 2, 3 on screen → the common error and its fix →
  result again.
- **Test / verdict**: "I tried X for N days" → what I expected → what actually happened (with proof)
  → verdict in one sentence.
- **Myth vs reality**: the belief → test it live → the result → what to do instead.
- **News in 45 s**: what changed (source on screen) → what it means for *this viewer* → one thing to
  do about it.

## Long-form YouTube, 8-15 minutes

Decide the title and thumbnail **before** the script (see SKILL.md, step 3); the first 30 seconds
must confirm them.

| Beat | Time (10-min video) | Job |
|---|---|---|
| **Hook sequence** | 0:00-0:30 | Confirm the click, open the gap, show the payoff exists (hooks.md) |
| **Setup** | 0:30-1:30 | What we're doing, what you'll have by the end, what you need. Short |
| **Body: 3-5 chapters** | 1:30-8:30 | Each chapter: mini-hook → content → mini-payoff → "but"/"so" into the next |
| **Payoff** | 8:30-9:30 | The full result, explicitly delivered ("that's the working agent, the code is linked") |
| **Close** | last 20-30 s | One ask, tied to the next video on the same topic. No long goodbye |

Rules for the body:

- Put the strongest chapter second, not last. Viewers who leave early should still have seen it.
- Every chapter shows something on screen. A talking head with nothing to look at is a podcast.
- Name what's coming before a long or technical part ("this next bit is the one that took me two
  days") so a dip doesn't turn into a cliff.
- Mid-video asks (subscribe, sponsor) go after a payoff, never before the first one.

### Long-form skeletons for tech

- **Build log**: the goal and the finished thing (hook) → plan → attempt 1 → what broke → the fix →
  the result → what I'd do differently.
- **Tutorial**: finished result → prerequisites (versions!) → steps as chapters → the error everyone
  hits → recap with the final code/prompt linked.
- **X vs Y**: the decision the viewer faces → criteria → same task in both, side by side → scores →
  verdict by use case ("pick X if…, Y if…").
- **Explainer**: the question → an analogy the viewer already knows → the real mechanism (with a
  diagram) → where the analogy breaks → why it matters for them.

## Calls to action

- One per video. Pick the one that matches the goal in `creator.md`: follow/subscribe (growth),
  comment a question (ideas + engagement), save/send (reach on Instagram), the long video (Shorts
  feeding long-form), a link (product or newsletter).
- Give a reason: "follow for the part where I deploy it" beats "follow for more".

## Making screen content watchable

- Zoom in on the part that matters; nobody can read a full 4K desktop on a phone.
- Large font in the editor and terminal (at least 2× normal), dark or light consistently.
- Cut waiting time: speed up installs and model output, or cut to the result.
- Hide secrets: API keys, emails, tokens, private repos, browser tabs. Check every frame.
- Show real outputs. Never fake a UI or an output; if a demo failed, that can be the video.
